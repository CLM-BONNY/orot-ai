# T02. 데이터와 머신러닝의 판단 기준

이 트랙에서는 모델이 시험 문제를 몰래 본 상황과 실제로 일반화한 상황을 구분한다. 앞 트랙의 벡터·손실·조건부 확률을 실제 데이터와 연결한다.

<a id="ch05"></a>
## CH05. 데이터 설계·분할·누수

- 선수 학습: CH01, CH03
- 개념 ID: `feature`, `label`, `data-quality`, `train-validation-test`, `data-leakage`, `distribution-shift`
- 학습 목표: 예측 시점에 사용 가능한 특징을 고르고 실제 사용 조건에 맞게 데이터를 나눈다.

<a id="ch05-p01"></a>
### CH05-P01. 데이터는 정답이 적힌 표보다 넓은 개념이다

사용자가 다음 퀴즈를 틀릴지 예측한다고 하자. 입력 특징은 과거 정답률, 이전에 읽은 페이지, 현재 문제 난이도일 수 있다. 레이블은 실제로 그 문제를 맞혔는지다. 특징과 레이블을 정하기 전에 “언제 예측하는가”를 정해야 한다. 문제를 풀기 전에 예측한다면 제출 후 계산한 점수는 입력에 쓸 수 없다.

데이터 품질에는 누락과 오타만 있는 것이 아니다. 정답 기준이 사람마다 다르거나 어려운 문제를 포기한 사용자가 데이터에 남지 않는 경우도 있다. 기록된 정답률은 사이트를 끝까지 이용한 사람의 값일 수 있다. 데이터가 어떻게 만들어지고 어떤 사람이 빠졌는지 알아야 결과의 적용 범위를 판단할 수 있다.

문제 ID를 숫자로 저장했다고 크기 차이가 의미를 갖는 것은 아니다. ID 100이 ID 50보다 두 배 어려운 것이 아니기 때문이다. 수치형·범주형·텍스트·시계열 같은 자료의 성격에 맞춰 표현을 정하자. 표현 방식은 모델이 볼 수 있는 관계를 바꾼다.

<a id="ch05-p02"></a>
### CH05-P02. 학습·검증·테스트는 서로 다른 역할이다

학습 세트는 파라미터를 맞추고, 검증 세트는 모델과 설정을 선택하며, 테스트 세트는 선택이 끝난 모델을 최종 점검한다. 연습 문제·모의고사·최종 시험에 비유할 수 있다. 최종 시험 점수를 보고 설정을 계속 바꾸면 그 시험도 사실상 연습에 쓰게 된다.

분할 방법은 실제 사용을 닮아야 한다. 미래 사용량을 예측하면 과거로 학습하고 미래로 평가하는 시간 순서가 중요하다. 새로운 사용자의 성능이 궁금하면 같은 사용자의 기록이 양쪽에 섞이지 않게 그룹으로 나누는 방법을 검토한다. 다만 기존 사용자의 미래 행동이 목적이라면 사용자 분리만이 정답은 아니다.

교차검증은 자료를 여러 번 나누어 선택의 안정성을 보는 방법이다. 무작위 K-fold가 모든 상황에 적절한 것은 아니다. 시간·사용자·기관처럼 샘플 간 의존성이 있다면 그 구조를 반영해야 한다. 테스트 세트를 나누는 비율보다 어떤 일반화를 측정하는지가 먼저다.

<a id="ch05-p03"></a>
### CH05-P03. 누수는 모델이 미래를 훔쳐보는 일이다

전체 자료에서 평균을 구해 정규화한 뒤 학습·테스트를 나누면 테스트 분포가 전처리 학습에 들어간다. 평균·결측값 대체·특징 선택 같은 학습형 변환은 학습 세트에서만 맞추고, 검증·테스트에는 같은 변환을 적용해야 한다. 교차검증에서도 각 학습 fold 안에서 새로 맞춰야 한다.

정답 설명에 있는 문장을 입력으로 넣고 오답 예측을 하는 경우는 더 직접적인 누수다. 완전히 같은 문서나 거의 같은 문제를 양쪽에 넣는 중복도 성능을 부풀릴 수 있다. 이름을 가린 데이터라도 생성 과정에서 정답 정보가 섞일 수 있으므로 특징 목록만 훑어서는 충분하지 않다.

실제 운영에서 성능이 떨어지면 누수뿐 아니라 분포 변화도 의심한다. 초보자용 데이터로 평가한 뒤 전문가가 주로 쓰는 서비스에 적용하면 입력과 목표가 달라질 수 있다. 학습·평가·운영의 차이를 기록하는 것은 모델 선택만큼 중요하다.

#### CH05-Q02 · 분할 설계

<a id="ch06"></a>
## CH06. 선형 회귀·로지스틱 회귀·손실

- 선수 학습: CH02, CH04, CH05
- 개념 ID: `linear-regression`, `logistic-regression`, `sigmoid`, `mse`, `cross-entropy`, `regularization`
- 학습 목표: 연속값 예측과 분류를 구분하고 출력·손실의 조합을 설명한다.

<a id="ch06-p01"></a>
### CH06-P01. 선형이라는 말은 무엇을 제한하는가

선형 회귀는 입력 특징의 가중합과 편향으로 연속값을 예측한다. 자료 길이와 문제 수로 생성 시간을 추정하는 간단한 기준선에 사용할 수 있다. 입력이 한 개면 직선이지만 여러 개면 고차원 공간의 평면을 생각할 수 있다. 중요한 것은 원래 세계가 직선이라는 가정이 아니라 선택한 특징을 선형으로 결합한다는 구조다.

예를 들어 x의 제곱을 새 특징으로 넣으면 `w₁x+w₂x²+b`는 x에 대해서는 곡선이지만 파라미터 w에 대해서는 선형이다. 특징을 어떻게 만들었는지가 표현력을 바꾼다. 대신 특징이 늘면 복잡성과 과적합 위험도 함께 본다.

평균제곱오차 MSE는 오차를 제곱해 평균한다. 큰 오차에 더 큰 벌점을 주므로 이상치에 민감할 수 있다. 평균절대오차 MAE는 다른 특성을 갖는다. 어느 손실이 적합한지는 실제로 큰 실수를 얼마나 심각하게 보는지와 연결된다.

<a id="ch06-p02"></a>
### CH06-P02. 이름은 회귀지만 분류에 쓰는 모델

로지스틱 회귀는 선형 점수 z를 sigmoid `1/(1+e^-z)`에 통과시켜 이진 클래스의 확률을 모델링한다. 이름의 회귀 때문에 연속값 예측만 한다고 생각하면 안 된다. 그 확률을 임곗값과 비교해 최종 클래스로 바꾼다.

이진 교차 엔트로피는 `-[y log p +(1-y) log(1-p)]`다. 정답이 1인데 p가 0에 가까우면 크게 벌점을 받는다. 틀리면서 확신하는 예측을 강하게 다루는 성질이 있다. 구현에서는 수치 안정성을 위해 확률을 직접 로그 계산하는 대신 logits를 받는 손실 함수를 쓰기도 한다.

모델이 0.7을 출력했다고 자동으로 사실상 70% 정확하다고 단정할 수는 없다. 확률 보정 상태를 확인해야 한다. 또한 임곗값 0.5는 관례적 선택이지 사용자 문제의 정답이 아니다. 오답 위험 알림의 비용 구조에 맞춰 바꿀 수 있다.

<a id="ch06-p03"></a>
### CH06-P03. 정규화와 단순 기준선의 힘

특징이 많고 자료가 적으면 모델이 우연한 패턴을 과하게 따라갈 수 있다. L2 정규화는 보통 가중치 제곱합에 벌점을 더해 지나치게 큰 가중치를 억제한다. L1은 절댓값 합을 사용하며 일부 가중치가 0이 되는 희소한 해를 유도할 수 있다. 목적함수에 무엇을 더하는지 이해하면 설정값을 해석하기 쉬워진다.

정규화는 정답 정보를 새로 만들지 않는다. 잘못된 레이블과 누수는 따로 고쳐야 한다. 특징의 단위가 다르면 가중치 벌점의 상대적 의미도 바뀔 수 있어, 스케일링과 정규화를 함께 고려한다.

복잡한 모델을 쓰기 전에 선형·로지스틱 회귀를 기준선으로 만들면 입력·분할·지표의 오류를 빨리 찾을 수 있다. 선형 모델이 잘 작동한다면 운영이 간단할 수 있고, 잘 안 된다면 어떤 상호작용과 비선형성을 놓치는지 살펴볼 수 있다. 단순함은 성능이 나쁘다는 뜻이 아니다.

#### CH06-Q02 · 임곗값 판단

<a id="ch07"></a>
## CH07. 트리·앙상블·비지도학습

- 선수 학습: CH05, CH06
- 개념 ID: `decision-tree`, `random-forest`, `gradient-boosting`, `clustering`, `k-means`, `pca`
- 학습 목표: 대표 모델의 학습 방식을 비교하고 정답 없는 분석의 해석 한계를 설명한다.

<a id="ch07-p01"></a>
### CH07-P01. 질문을 이어 붙이는 결정트리

“읽은 페이지가 2개 미만인가?”, “이전 정답률이 50% 미만인가?”처럼 조건을 따라가며 예측하는 구조가 결정트리다. 여러 특징 사이의 비선형 관계를 분기로 표현할 수 있다. 입력마다 예측 경로를 확인할 수 있지만, 깊은 트리가 언제나 쉽게 해석되는 것은 아니다.

트리를 너무 깊게 키우면 각 잎이 소수 사례만 기억할 수 있다. 자료를 조금 바꿨는데 분기가 크게 달라지는 불안정성도 있다. 깊이와 잎의 최소 샘플 수 등을 검증 자료로 선택하는 이유다. 범주 표현 방식이나 목표 누수는 트리를 쓴다고 자동 해결되지 않는다.

트리의 특징 중요도는 인과관계가 아니다. 정답률 예측에 접속 시간이 중요하게 나왔다고 밤에 접속하게 하면 성적이 오른다는 결론은 낼 수 없다. 상관된 특징, 선택 편향, 중요도 계산 방식의 편향을 함께 생각해야 한다.

<a id="ch07-p02"></a>
### CH07-P02. 여러 모델을 모으는 두 방식

랜덤 포레스트는 자료와 특징의 무작위성을 이용해 다양한 트리를 만들고 결과를 모은다. 서로 비슷하게 틀리는 모델을 단순히 많이 쌓는 것보다 오류가 덜 겹치는 모델들의 결합이 유리할 수 있다. 여러 채점자의 평균에 비유할 수 있지만, 채점자들이 같은 오해를 공유하면 평균도 틀린다.

그레이디언트 부스팅은 기존 모델의 손실을 줄이는 방향으로 새 모델을 순차적으로 더한다. “앞 모델이 부족한 부분을 다음 모델이 보완한다”는 비유가 도움이 된다. 정확히는 항상 오답 사례만 다시 학습하는 것이 아니라 선택한 손실의 기울기 정보를 이용하는 방식이다.

정형 데이터에서는 이런 모델들이 강한 기준선이 될 수 있다. 어떤 모델이 항상 최고라는 규칙은 없다. 데이터 크기·특징·추론 비용·해석 요구와 같은 조건에서 비교해야 한다. 표본 분할이나 튜닝 예산이 다르면 공정한 비교도 아니다.

<a id="ch07-p03"></a>
### CH07-P03. 정답 없이 모으고 줄여보기

군집화는 레이블 없이 비슷한 사례를 묶는 작업이다. K-means는 K개 중심을 두고 각 점을 가까운 중심에 할당하며 거리 제곱합을 줄인다. 공부 시간이 1~10이고 문제 수가 1~1000이면 스케일이 큰 축이 거리를 지배할 수 있다. 구 모양이 아닌 군집이나 이상치에도 한계가 있다.

군집 번호는 의미나 순위가 아니다. 0번 군집이 초보자라는 이름은 분석자가 자료를 확인한 뒤 붙이는 해석이다. 군집이 보기 좋게 나왔다는 사실만으로 실제 제품 의사결정에 유용하다고 할 수도 없다.

PCA는 데이터가 많이 변하는 방향으로 선형 축을 찾아 차원을 줄인다. 분산을 잘 보존하는 방향이 정답 분류에 가장 유리한 방향이라는 보장은 없다. 2차원 그림에서 두 집단이 겹쳐 보인다고 원래 공간에서도 구분할 수 없다고 단정하지 말자. 시각화는 질문을 만드는 도구이지 최종 판결이 아니다.

A. 둘 다 언제나 신경망보다 우수하다.
B. 부스팅은 모든 모델을 완전히 독립적으로 학습한다.

#### CH07-Q02 · 결과 해석

## CH08. 평가 지표와 모델 선택

- 선수 학습: CH03, CH05, CH06
- 개념 ID: `confusion-matrix`, `precision`, `recall`, `f1`, `roc-auc`, `pr-curve`, `threshold`, `error-analysis`
- 학습 목표: 사용자 비용에 맞는 지표와 임곗값을 선택하고 평균 점수 뒤의 실패를 찾는다.

<a id="ch08-p01"></a>
### CH08-P01. 정확도만 높으면 좋은 모델일까

1,000개 사례 중 위험 사용자가 10명이면 모두 정상이라고 해도 정확도는 99%다. 그러나 위험 사용자는 한 명도 찾지 못한다. 혼동행렬의 TP·FP·FN·TN은 이 문제를 분해한다. TP는 위험을 위험으로 맞힌 경우, FP는 정상인데 위험으로 알린 경우, FN은 위험을 놓친 경우다.

정밀도는 `TP/(TP+FP)`, 재현율은 `TP/(TP+FN)`이다. TP=8, FP=12, FN=2이면 정밀도 40%, 재현율 80%다. F1은 둘의 조화평균으로 약 53.3%다. 분모가 0인 상황의 처리는 평가 도구 설정을 확인해야 한다.

알림을 잘못 보내는 비용과 위험 사용자를 놓치는 비용은 다르다. 하나의 지표가 모든 상황에 적절하지 않다. F1도 참음성이나 비용 차이를 직접 표현하지 않으므로, 필요하면 비용 기반 기준과 운영 제약을 함께 둔다.

<a id="ch08-p02"></a>
### CH08-P02. 순위를 잘 매기는 것과 결정이 좋은 것은 다르다

ROC-AUC는 여러 임곗값에서 양성과 음성의 순위 구분 능력을 요약한다. 선택한 임곗값에서의 정밀도를 바로 알려주지는 않는다. 양성이 드문 문제에서는 PR 곡선과 정밀도·재현율을 함께 보면 실제 알림의 쓸모를 판단하기 쉽다. AP와 사다리꼴 방식의 PR-AUC는 계산 정의가 같지 않을 수 있으므로 보고한 지표를 정확히 적자.

운영에서 시간당 알림을 최대 100개만 확인할 수 있다면 상위 100개에서의 정밀도가 중요할 수 있다. 같은 AUC라도 필요한 구간의 성능은 다를 수 있다. 임곗값도 검증 자료에서 선택하고, 최종 테스트 점수를 보며 계속 바꾸지 않는다.

회귀에서는 MAE와 RMSE처럼 오차 크기를 다르게 강조하는 지표가 있다. 임의의 점수 이름보다 사용자에게 어떤 실수가 큰 손해인지 먼저 생각하자. 지표는 그 판단을 수치로 표현하는 도구다.

<a id="ch08-p03"></a>
### CH08-P03. 오류를 묶어보면 다음 작업이 보인다

전체 정확도가 같아도 긴 글에서만 틀리는 모델과 특정 개념에서만 틀리는 모델은 개선 방법이 다르다. 자료 길이·주제·난이도 같은 구간별 성능을 살펴보자. 다만 아주 작은 구간의 점수를 과하게 해석하지 않고 사례 수를 함께 적는다.

틀린 사례를 읽으면 레이블 오류, 입력 부족, 모호한 정답, 모델 한계를 구분할 수 있다. 레이블을 정리해야 할 문제를 더 큰 모델로 해결하려고 하면 비용만 커질 수 있다. 오류 분석은 실패를 비난하는 과정이 아니라 다음 실험을 선택하는 과정이다.

모델을 고른 뒤에는 속도와 비용도 함께 기록한다. 정확도 1%p 향상을 위해 응답이 열 배 느려진다면 사용 목적에 따라 받아들이기 어려울 수 있다. 품질·시간·비용의 절충안을 명시하면 “최고 모델” 대신 “우리 서비스에 적합한 설정”을 선택할 수 있다.
