# T03. 딥러닝이 학습되는 과정

신경망을 신비한 상자 대신 입력·변환·손실·갱신으로 읽는다. 코드는 PyTorch 문법을 설명하기 위한 최소 예시이며, 패키지 설치나 실행 환경을 이 문서가 제공하는 것은 아니다.

<a id="ch09"></a>
## CH09. 텐서와 신경망의 표현

- 선수 학습: CH02, CH04
- 개념 ID: `tensor-shape`, `broadcasting`, `batch`, `mlp`, `activation`, `logits`
- 학습 목표: 신경망의 축을 추적하고 비선형 활성화가 필요한 이유를 설명한다.

<a id="ch09-p01"></a>
### CH09-P01. 모양을 읽으면 계산이 보인다

한 사용자를 특징 세 개로 표현하고 사용자 네 명을 묶으면 입력 모양은 `[4,3]`이다. 선형 층이 특징을 여섯 개로 바꾸면 출력은 `[4,6]`이다. 첫 축은 샘플, 둘째 축은 특징이다. 모델은 배치 안의 서로 다른 사용자를 하나의 사용자로 합치는 것이 아니라 각 행에 같은 변환을 적용한다.

브로드캐스팅은 크기가 1인 축 등을 확장해 연산할 수 있게 하는 규칙이다. `[4,6]` 출력에 `[6]` 편향을 더하면 각 행에 같은 편향이 적용된다. 편리하지만 잘못된 정답 모양이 우연히 연산 가능한 경우도 있다. 예측 `[4,1]`과 정답 `[4]`를 빼면 의도와 달리 `[4,4]`가 될 수 있으므로 손실 직전에 모양을 확인하자.

숫자 자료형과 장치도 확인해야 한다. 정수 토큰 ID와 실수 임베딩은 역할이 다르다. CPU에 있는 텐서와 GPU 모델을 섞으면 오류가 날 수 있다. 모양·자료형·장치는 딥러닝 코드 디버깅의 첫 세 질문이다.

<a id="ch09-p02"></a>
### CH09-P02. 층을 쌓기만 하면 표현력이 늘까

선형 변환 두 개를 비선형 함수 없이 이어 붙이면 다시 하나의 선형 변환으로 합칠 수 있다. 그래서 다층 퍼셉트론 MLP는 선형 층 사이에 ReLU 같은 비선형 활성화를 넣는다. ReLU는 `max(0,x)`로 음수를 0으로 만든다. 여러 구간을 다르게 다루면서 단순 가중합보다 복잡한 관계를 표현할 수 있다.

입력이 공부 시간과 복습 횟수일 때, 일정 조건을 넘어서야 성과가 크게 바뀌는 관계를 생각해보자. 신경망은 중간 표현을 학습해 이런 상호작용을 표현할 수 있다. 그러나 어떤 조건이 실제로 학습되었는지는 따로 검증해야 한다. 뉴런 하나가 반드시 특정 인간 개념을 맡는다고 단정할 수 없다.

출력 logits는 아직 확률로 정규화하지 않은 점수다. 다중 클래스에서는 softmax로 각 점수를 양수로 바꾸고 합이 1이 되게 할 수 있다. 학습 손실이 logits를 직접 받도록 설계되어 있다면 미리 softmax를 두 번 적용하면 안 된다.

<a id="ch09-p03"></a>
### CH09-P03. 최소 신경망의 모양 추적

아래 코드는 네 샘플을 세 특징에서 두 클래스 점수로 바꾼다. 정답 값은 넣지 않았으므로 학습이 아니라 순전파 예시다.

```python
import torch
from torch import nn

torch.manual_seed(7)
x = torch.randn(4, 3)
model = nn.Sequential(
    nn.Linear(3, 6),
    nn.ReLU(),
    nn.Linear(6, 2),
)
logits = model(x)
assert logits.shape == (4, 2)
```

중간 결과는 `[4,6]`, 최종 결과는 `[4,2]`다. 두 숫자는 두 클래스의 상대 점수이지 문제 두 개의 정답이 아니다. 이 출력을 해석하려면 학습 때 정한 클래스 순서와 목표 정의가 필요하다.

모형을 만들었지만 아직 학습하지 않았다. 코드가 정상 실행되고 출력 모양이 맞는 것, 손실이 줄어드는 것, 새 자료에서 잘 맞는 것은 서로 다른 검증 단계다. 각 단계를 나누면 오류를 좁히기 쉽다.

## CH10. 역전파와 PyTorch 학습 루프

- 선수 학습: CH04, CH09
- 개념 ID: `forward-pass`, `backpropagation`, `autograd`, `optimizer`, `gradient-accumulation`, `train-eval-mode`
- 학습 목표: 순전파·역전파·갱신을 구분하고 학습 코드의 기본 오류를 찾는다.

<a id="ch10-p01"></a>
### CH10-P01. 계산을 따라 앞으로, 민감도를 따라 뒤로

순전파는 입력에서 예측과 손실까지 계산하는 과정이다. 역전파는 합성함수의 미분인 연쇄법칙을 적용해 손실이 각 파라미터에 얼마나 민감한지 계산한다. 각 층이 정답을 직접 받는 것이 아니라 앞뒤 계산을 통해 기울기가 전달된다.

예를 들어 `a=wx`, `L=(a-y)^2`이면 `dL/dw=(dL/da)(da/dw)`다. PyTorch의 autograd는 이런 계산 관계를 기록하고 필요한 기울기를 구한다. `backward()`는 파라미터를 갱신하는 명령이 아니다. 계산한 기울기를 `.grad`에 쌓는다.

공장 생산량의 원인을 역으로 추적하는 비유가 가능하다. 최종 오차가 생겼을 때 어떤 조절 손잡이가 얼마나 영향을 주는지 계산한다. 다만 역전파는 사람이 이유를 설명하는 절차가 아니라 미분 가능한 계산의 민감도를 계산하는 알고리즘이다.

<a id="ch10-p02"></a>
### CH10-P02. 학습 루프의 네 동작

최소 루프는 기울기 초기화, 순전파와 손실, 역전파, optimizer 갱신으로 구성된다.

```python
import torch
from torch import nn

torch.manual_seed(7)
model = nn.Linear(3, 2)
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
loss_fn = nn.CrossEntropyLoss()
x = torch.randn(4, 3)
y = torch.tensor([0, 1, 0, 1], dtype=torch.long)

model.train()
optimizer.zero_grad()
logits = model(x)
loss = loss_fn(logits, y)
loss.backward()
optimizer.step()
```

`zero_grad()`를 생략하면 이전 기울기와 더해진다. 의도적인 gradient accumulation도 있지만, 그때는 손실 스케일과 갱신 주기를 설계해야 한다. `step()` 없이 `backward()`만 반복하면 가중치는 학습되지 않는다. 분류 정답은 위 예시에서 샘플별 클래스 인덱스이며 logits와 같은 모양이 아니다.

<a id="ch10-p03"></a>
### CH10-P03. 평가 모드와 기울기 비활성화는 다른 스위치다

`model.eval()`은 dropout이나 batch normalization처럼 모드에 따라 행동이 바뀌는 층을 평가 동작으로 전환한다. 이것만으로 기울기 기록이 꺼지는 것은 아니다. `torch.no_grad()` 또는 적절한 추론 모드는 기울기 추적과 관련된 동작을 제어한다. 보통 평가에서는 두 역할을 함께 고려한다.

```python
model.eval()
with torch.no_grad():
    predictions = model(x).argmax(dim=-1)
```

새 모델을 디버깅할 때 작은 자료 몇 건을 먼저 과하게 맞춰보는 방법이 유용하다. 쉬운 자료도 못 맞추면 입력·정답·손실·갱신 경로를 의심할 수 있다. 작은 자료를 외우는 데 성공했다고 일반화가 입증된 것은 아니다. 이 검사는 학습 배선이 작동하는지 확인하는 단계다.

<a id="ch11-p01"></a>
### CH11-P01. 연습장을 외우는 것과 실력이 느는 것

과적합은 학습 자료의 특수한 패턴까지 맞춰 새로운 자료에서 잘 작동하지 않는 상태를 말한다. 과소적합은 선택한 표현이나 학습 과정이 문제의 관계를 충분히 포착하지 못하는 상태다. 학습·검증 모두 나쁘다면 과소적합뿐 아니라 레이블 오류, 학습 실패도 가능하다. 곡선 모양은 단서이지 원인의 확정 판정이 아니다.

학습 손실은 줄고 검증 손실이 증가하면 더 학습하는 것이 해로울 수 있다. early stopping은 검증 지표를 관찰해 좋은 시점의 모델을 고르는 방법이다. 테스트 자료로 멈출 시점을 정하면 테스트의 독립성이 깨진다.

문제집 답을 외우는 비유가 도움이 되지만 모델은 사람처럼 의식적으로 외우는 것이 아니다. 파라미터와 학습 절차가 훈련 자료에 지나치게 맞춰지는 것이다. 더 많은 자료도 중복·편향·오류가 많으면 해결책이 되지 않을 수 있다.

<a id="ch11-p02"></a>
### CH11-P02. 서로 다른 조절 장치를 구분하기

Dropout은 학습 중 일부 활성값을 무작위로 제거하는 방식으로 특정 연결에 과하게 의존하는 것을 줄이려 한다. 평가 때도 그대로 무작위로 끄는 것이 기본 동작은 아니다. Weight decay는 가중치를 작게 만드는 방향의 갱신을 더한다. L2 벌점과의 정확한 관계는 optimizer 방식에 따라 달라질 수 있다.

SGD, momentum, Adam은 파라미터 갱신 방식이 다르다. Adam은 기울기 통계를 이용해 파라미터별 갱신 크기를 조절하지만 학습률 설정이 필요 없다는 뜻은 아니다. 학습률 스케줄과 warmup도 초반 불안정을 줄이기 위해 사용할 수 있다. 모든 모델에 같은 설정이 최선이라고 가정하지 않는다.

Batch normalization과 layer normalization은 정규화하는 축과 통계 사용 방식이 다르다. 이름에 normalization이 들어간다고 입력 표준화와 같은 작업은 아니다. 특히 배치 크기·학습 모드·추론 모드에 따른 차이를 확인해야 한다.

<a id="ch11-p03"></a>
### CH11-P03. 재현 가능한 실험 만들기

실험마다 seed, 데이터 분할, 전처리, 코드·패키지·모델 버전을 남긴다. 같은 seed도 모든 장치와 연산에서 완벽한 동일 결과를 보장하지는 않는다. 재현성은 seed 한 줄이 아니라 조건 기록과 변동 확인의 문제다.

설정 다섯 개를 동시에 바꿔 성능이 좋아지면 무엇이 기여했는지 알기 어렵다. 하나씩 바꾸는 실험이나 구성 요소를 제거하는 ablation으로 원인을 확인한다. 반복 실행 결과의 분포도 보면 우연한 개선을 줄일 수 있다.

우리 학습 사이트에서 모델 교체와 프롬프트 수정과 문제 수 변경을 한꺼번에 하면 속도가 빨라진 원인을 분리하기 어렵다. 같은 원리가 신경망 학습과 API 기반 AI 서비스 모두에 적용된다. 먼저 기준선을 고정하고 변경 이유와 예상 효과를 적자.

## CH12. CNN·RNN과 구조적 가정

- 선수 학습: CH09, CH10
- 개념 ID: `cnn`, `convolution`, `pooling`, `rnn`, `lstm`, `gru`, `inductive-bias`
- 학습 목표: 데이터 구조에 맞는 모델 가정과 그 한계를 설명한다.

<a id="ch12-p01"></a>
### CH12-P01. CNN은 왜 이미지를 작은 창으로 볼까

이미지에서 모서리나 질감은 여러 위치에 나타난다. CNN의 합성곱은 작은 영역에 같은 가중치를 적용한다. 지역 연결과 가중치 공유로 위치마다 별도 규칙을 배우는 부담을 줄인다. 사진 구석에서 찾은 경계 감지기를 다른 위치에도 쓰는 비유를 떠올릴 수 있다.

필터 크기는 한 번에 보는 범위, stride는 이동 간격, padding은 경계 처리와 출력 크기에 영향을 준다. 여러 층을 쌓으면 넓은 영역의 정보를 조합할 수 있다. Pooling은 영역을 요약하지만 세밀한 위치 정보가 줄 수 있다.

가중치 공유는 위치 변화에 대한 유용한 성질을 주지만 모든 CNN이 임의의 위치·크기·회전에 완전히 불변인 것은 아니다. 데이터 증강과 구조 선택이 필요하다. 이런 사전 가정을 inductive bias라고 부른다. 학습을 돕는 가정이지만 문제와 맞지 않으면 제약이 된다.

<a id="ch12-p02"></a>
### CH12-P02. RNN은 이전 상태를 들고 다음 입력으로 간다

문장은 순서에 따라 의미가 달라진다. RNN은 현재 입력과 이전 은닉 상태를 받아 새 상태를 만든다. 앞의 내용을 요약한 메모를 들고 다음 단어를 읽는 비유다. 같은 변환이 여러 시점에 반복 적용된다.

긴 시퀀스를 따라 기울기가 반복해서 곱해지면 작아지거나 커지는 문제가 생길 수 있다. LSTM과 GRU는 정보를 유지하고 갱신하는 게이트를 사용해 이를 완화하려는 구조다. 긴 의존성을 항상 완벽하게 기억한다는 뜻은 아니다.

순차적 의존성 때문에 학습의 시점별 계산을 병렬화하기 어려운 측면도 있다. Transformer가 주목받은 배경을 이해하려면 이런 차이를 알아야 한다. 그렇다고 모든 시계열 문제에서 RNN이 무조건 부적절한 것은 아니다. 데이터·지연·자원 조건에서 평가한다.

<a id="ch12-p03"></a>
### CH12-P03. 구조 선택은 정답을 미리 넣는 방식이다

CNN은 근처 패턴과 위치 공유, RNN은 순서와 상태라는 가정을 담는다. Transformer는 토큰 사이의 관계를 Attention으로 계산한다. 어떤 구조든 데이터에 대한 가정과 계산 비용을 함께 가진다. 최신이라는 이유만으로 다른 선택을 지울 필요는 없다.

이미지 분류와 객체 탐지, 의미 분할도 목표가 다르다. 분류는 이미지의 클래스, 탐지는 객체 위치와 클래스, 분할은 픽셀별 클래스를 다룬다. 입력이 모두 사진이어도 출력과 평가 지표가 달라진다. NLP의 문장 분류·토큰 분류·생성도 같은 관점으로 구분할 수 있다.

우리 사이트는 모델을 직접 학습시키기보다 외부 LLM을 호출하지만, 구조의 가정을 알면 입력 길이·순서·추론 비용의 제약을 이해하기 쉽다. 모델 구조 공부와 서비스 구현은 서로 떨어진 주제가 아니다.

CNN의 대표적인 설계 특징은?
