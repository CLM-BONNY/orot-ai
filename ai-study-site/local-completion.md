## 실행

앱 폴더에서 `python3 run_local.py --production`을 실행하고 `http://127.0.0.1:5178/notebook`에 접속한다. 화면을 바꿨다면 먼저 `frontend`에서 `npm run build`를 실행한다. 이 Mac의 검증 Python은 `/Users/kimmandoo/.pyenv/versions/3.10.12/bin/python3`이다.

- 일반 개발: `python3 run_local.py` (Vite 5178 → API 8018 → 모델 11535)
- 운영 빌드: `python3 run_local.py --production` (화면·API 5178 → 모델 11535)
- 모델 시작 생략: `python3 run_local.py --production --without-model`
- 별도 검증 주소: `AI_STUDY_FRONTEND_PORT=5179 python3 run_local.py --production`
- 정적 빌드 HTTP 점검: `python3 verify_local.py --url http://127.0.0.1:5178`

실행기는 기존 모델 서버를 재사용하고 자신이 시작한 프로세스만 Ctrl+C로 종료한다. 운영 빌드는 단일 worker를 유지한다. 현재 AI 동시 실행 제한·중복 요청 캐시는 프로세스 메모리에 있어 worker 수를 늘리면 공유되지 않는다.

`frontend/dist`, `backend`, `run_local.py`, 형제 폴더 `../data-design/data`를 함께 유지한다. 기본 콘텐츠 경로는 이 구조를 따른다. 다른 위치에서는 `CONTENT_DATA_DIR`, `FRONTEND_DIST_DIR`를 설정한다. `.env.local`은 이 Mac의 모델 경로를 포함하는 로컬 설정이며 외부 배포물에 포함하지 않는다.

## 기록 보존

`나의 학습 → 학습 기록 백업·가져오기`에서 JSON 파일로 이동한다. 메모·객관식 이력·자기평가·별표·읽기·이어 읽기·AI 세트와 전체 문제를 보관한다. 서버에 전송하지 않는다. 브라우저 다운로드 폴더에 저장되므로 파일을 직접 보관한다.

가져오기는 다음 순서로 진행한다.

1. 20MB 이하 파일을 선택한다. 기존 데이터 계약의 JSON Schema, 문제 SHA-256, 채점 일치, 소유자와 생성 세트 연결을 검사한다.
2. 개수를 확인하고 ‘확인한 기록 가져오기’를 누른다.
3. 현재 로컬 프로필로 기록을 합친다. 기존 기록을 삭제하지 않는다. 같은 파일을 반복해서 가져와도 중복 생성하지 않는다.
4. 같은 ID의 내용이 다르면 전체 트랜잭션을 취소한다. 읽기와 이어 읽기는 더 최근 시각을 기준으로 합친다. 같은 문제·개정의 별표는 하나만 유지한다.
5. 성공하면 새로고침해 읽기·개인 기록을 함께 반영한다. 이전 콘텐츠 버전의 기록과 문제 스냅샷을 유지한다.

해시는 우발적인 변조를 검출하는 수단이다. 백업 내용의 출처·정답 정확성을 인증하지는 않는다. 수정된 메모가 같은 ID로 이미 존재하면 자동 덮어쓰기하지 않고 가져오기를 취소한다.

## 나중에 진행할 AWS 작업

공개 URL·AWS 리소스·GPU 서버는 생성하지 않았다. 현재 loopback 바인딩으로 이 Mac에서 사용한다. 모바일 점검은 데스크톱 브라우저의 화면 크기 검사이며 실제 휴대폰·Safari 검증은 남아 있다. 학습 콘텐츠와 AI 문제의 교육 품질 검수도 별도다.

AWS를 진행할 때 계정·리전·월 예산과 큰 모델 체크포인트·GPU 환경을 정한다. 현재 동기 생성은 약 49초 사례가 있어 API 진입점의 제한에 맞는 컨테이너 또는 비동기 작업 구성이 필요하다. 배포 시 HTTPS, 사용자 접근 제한, 요청량 제한, 모델 서버의 사설 접근, 프록시 제한 시간을 실제 환경에 맞춰 구현하고 다시 검증한다.

다음 스터디 작업은 동일한 문항·질문·실행 조건으로 반복 측정하는 성능 기준선 수집이다. 로컬 Qwen 결과와 향후 GPU 모델 결과는 분리한다.
